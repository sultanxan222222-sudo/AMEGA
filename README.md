# AMEGA

**AMEGA** is a two-part local-network transfer system for moving PS4 game package files (`.pkg`) from a Windows PC to a PS4 running a compatible HEN environment.

The product has two native applications:
- **AMEGA for Windows** — selects packages, discovers consoles, offers transfers, and reports progress.
- **AMEGA for PS4** — discovers Windows senders, asks the user to accept, receives and verifies packages, and exposes compatible installation actions.

AMEGA is intended to work over a trusted home Wi-Fi/LAN without a cloud account or internet connection.

## Project status — discovery hardening 0.2.1

Both prototype applications have been built successfully in GitHub Actions:
- Windows x64 self-contained application: [Windows build workflow](https://github.com/sultanxan222222-sudo/AMEGA/actions/runs/41334314970).
- PS4 homebrew package: [PS4 build workflow](https://github.com/sultanxan222222-sudo/AMEGA/actions/runs/41336127412).

The PS4 PKG is 6,619,136 bytes and was generated by the OpenOrbis package toolchain. The build artifact ZIP was checked for archive integrity. **Neither package has yet been installed and tested on the user's actual PC/PS4 hardware.** This is a discovery prototype, not a release-ready game-transfer product.

## Design priorities

1. **User approval on both ends.** Nothing transfers or installs silently.
2. **Integrity first.** Every package is checked with SHA-256 before it is marked complete.
3. **Resume, do not restart.** Interrupted transfers should continue from verified byte ranges.
4. **HTTP Range correctness.** PS4 package-install workflows can request arbitrary byte ranges; a whole-file-only HTTP response is not sufficient.
5. **No destructive cleanup.** AMEGA never deletes the source package automatically.
6. **Separate transfer from installation.** Receiving a PKG and installing it are distinct actions.
7. **HEN compatibility is explicit.** HEN does not automatically mean a separate Remote Package Installer app is installed or running.
8. **Local-first.** Discovery and transfer stay on the local network.

## Current prototypes

**Windows:** select a PKG, calculate SHA-256, enumerate active IPv4 adapters and real subnet masks, send directed broadcasts plus bounded unicast discovery probes, and listen for nonce-validated PS4 replies on a separate UDP port. It exposes health and offer metadata only; it does not transfer or install files yet.

**PS4:** display a Russian-first screen, listen for PC discovery probes, reply directly to the observed PC address with a nonce-bound announcement, and show discovered computers. Startup uses SDL_CreateRenderer with accelerated/software fallback instead of mixing window-surface and renderer APIs. Cross currently selects a PC; it does not accept or download a package yet.

## Discovery hardening 0.2.0

The discovery design now follows proven LAN-discovery patterns from existing open-source senders: actual per-interface subnet masks, directed broadcast, bounded unicast fallback, and nonce correlation. See `docs/open-source-research.md` and `docs/protocol-v1.md`. CI success still does not prove a visible screen or real LAN discovery on the user's hardware.

## Next end-to-end milestone

1. Pair the discovered devices and authorize a single transfer.
2. Display the selected package on the PS4 and require explicit Accept / Decline.
3. Serve the selected PKG from Windows with correct HTTP byte-range semantics.
4. Receive into a safe staging directory with pause/resume.
5. Verify the final SHA-256 before showing completion.
6. Keep package installation as a separate, explicit action.

## Compatibility

The initial target is Windows 10/11 x64 and a PS4 running a compatible HEN/GoldHEN setup. Exact firmware and GoldHEN capabilities must be detected and verified; AMEGA will not assume that every HEN version exposes the same services.
