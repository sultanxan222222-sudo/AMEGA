# AMEGA development roadmap

A stage is complete only when its acceptance criteria pass. A source file or successful compile alone is not proof of end-to-end functionality.

## Stage 0 — foundation
- [x] Create repository and document architecture.
- [x] Define first protocol and security requirements.
- [x] Separate transfer from installation.
- [ ] Add shared protocol implementation and automated tests.

## Stage 1 — Windows sender
- [x] Native Windows UI in Russian.
- [x] PKG file picker and metadata preview.
- [x] LAN discovery beacon and nonce-validated reply listener.
- [x] Per-interface directed broadcast and bounded subnet unicast fallback.
- [x] Discovery remains available during background SHA-256 hashing.
- [x] Server-side accept validation for a fresh discovered receiver.
- [x] Streaming file endpoint with HTTP Range, Content-Range, ETag and token/IP gate.
- [ ] Add automated tests for accept denial, token expiry, source-IP binding, and Range edge cases.
- [ ] Implement PS4-side accept request and token handling.
- [ ] Transfer queue, progress/speed, cancel, pause, and resume.

Acceptance: the PS4 app on the same LAN can discover the sender, explicitly accept an offer, download a large test file, resume it, and verify SHA-256.

## Stage 2 — PS4 receiver
- [x] Native PS4 homebrew project and reproducible OpenOrbis build workflow (toolchain image pinned by digest).
- [x] Russian-first UI with visible sender list.
- [x] Listen for Windows discovery probes and send an immediate nonce-bound unicast reply.
- [x] SDL GameController input, raw Joystick fallback, and hot-plug handling.
- [x] Display local IPv4 address and startup diagnostics.
- [x] Prototype PKG generated by CI.
- [ ] Poll sender offer and display package name/size/digest summary.
- [ ] Explicit Accept / Decline actions for an actual transfer offer.
- [ ] Range-download client with safe staging and free-space check.
- [ ] Persist resume state and verify receiver-side SHA-256.
- [ ] Install and test the PKG on a real PS4 Pro with the target HEN/GoldHEN version.

Acceptance: PS4 discovers the Windows sender, accepts a test file, resumes after disconnect, and verifies the exact expected digest on real hardware.

## Stage 3 — installation adapter
- [ ] Detect GoldHEN built-in Remote Package Install capability separately from standalone Remote Package Installer and BinLoader.
- [ ] Add an adapter for a documented mechanism only after an application-level health check.
- [ ] Show exact installation state and useful errors.
- [ ] Verify behavior with a known safe test package.

Acceptance: installation is initiated only after explicit confirmation and success is reported only when the console mechanism confirms it.

## Stage 4 — release hardening
- [ ] Authenticated encrypted transport and user-visible pairing code.
- [ ] Negative security and malformed-input tests.
- [ ] Large-file and low-disk-space tests.
- [ ] Wi-Fi loss, app restart, and duplicate-transfer tests.
- [ ] Windows signing/release packaging strategy.
- [ ] Real PS4 Pro HEN test report and release notes.

## Release rule

Do not publish a release as ready until the Windows and PS4 artifacts have both been built, installed, and tested in the same end-to-end scenario.
